# MetaBCI 与 Unity 56车虚拟控制程序接口约定

## 1. 接口目的

MetaBCI 负责采集脑电数据、执行 FBSCCA 判决并输出刺激块标签。Unity 负责读取标签，根据当前动态映射状态控制对应的车辆、车辆组或全部车辆。

## 2. 判决结果文件

MetaBCI 每次完成判决后，覆写以下文件：

```text
demos/SwarmRobotDemos/algo/result.txt
```

文件编码为 UTF-8，内容只包含一个整数，不包含其他说明文字。

| 数值 | 含义 | Unity处理方式 |
| --- | --- | --- |
| `0` | 程序初始化 | 忽略 |
| `1-20` | 有效物理刺激块编号 | 按动态映射规则处理 |
| `21` | FBSCCA判决失败 | 忽略，不执行任何车辆命令 |

## 3. Unity读取要求

1. 将 `result.txt` 路径设置为 Inspector 可配置项，不要硬编码某台电脑的绝对路径。
2. 建议每隔 50 ms 检查一次文件修改时间。
3. 文件发生更新后，重新读取并使用 `int.TryParse` 解析标签。
4. 读取文件时应允许 MetaBCI 同时写入，并在内容为空、文件被占用或解析失败时短暂重试。
5. 文件读取可以在后台线程执行，但车辆和场景对象必须在 Unity 主线程更新。
6. 不要只比较标签值判断是否出现新结果，因为连续两次判决可能得到相同标签。
7. 收到 `21` 时只记录判决失败，不得沿用上一次命令。

## 4. 物理刺激块布局

刺激界面固定为 4 行 5 列，共 20 个物理刺激块：

| 行列 | 第1列 | 第2列 | 第3列 | 第4列 | 第5列 |
| --- | --- | --- | --- | --- | --- |
| 第1行 | `1: L1` | `2: 前进` | `3: R1` | `4: 切换区1` | `5: 切换区2` |
| 第2行 | `6: 左移` | `7: S/换挡` | `8: 右移` | `9: 切换区3` | `10: 切换区4` |
| 第3行 | `11: L2` | `12: 后退` | `13: R2` | `14: 切换区5` | `15: 切换区6` |
| 第4行 | `16: END` | `17: INIT` | `18: ALL` | `19: 切换区7` | `20: 切换区8` |

物理刺激编号和频率固定不变。界面切换只改变刺激块显示文字和逻辑含义。

## 5. 动态内容映射

### 5.1 主界面

主界面的车辆切换区按顺序显示车辆组 `A-H`。

- 车辆组最多为 8 组。
- 未配置的组仍保留对应闪烁刺激块，但不显示文字。
- 收到空刺激块编号时，不执行任何操作。
- 选择某个组后，控制范围切换为该组，并进入该组分界面。

### 5.2 车辆组分界面

每组最多包含 7 辆车，车辆名称由大写组名和数字组成，例如：

```text
A1 A2 A3 A4 A5 A6 A7 BACK
```

如果 A 组只有 3 辆车，则显示：

```text
A1 A2 A3 空 空 空 空 BACK
```

- 选择车辆后，控制范围切换为该车辆，并返回主界面。
- 选择 `BACK` 后返回主界面，不产生车辆控制命令。
- 收到空刺激块编号时，不改变当前状态。

### 5.3 特殊状态

- `7/S`：在挡位1和挡位2之间切换。
- `18/ALL`：将控制范围切换为全部车辆，并返回主界面。
- `16/END`、`17/INIT`：作为特殊功能命令交给 Unity 执行，具体效果由Unity项目定义。
- 其他车辆控制区标签作用于当前选中的单车、车辆组或全部车辆。

## 6. 配置文件

车辆组数、每组车辆数、主界面文字和分界面文字由以下文件定义：

```text
demos/SwarmRobotDemos/stim/NewFunc2/config.json
```

Unity应读取该配置，或者由双方保证Unity内部配置与该文件完全一致，避免动态映射状态不一致。

## 7. 当前通信流程

```text
刺激界面
  -> 通过 COM12 向博睿康 Trigger Box 发送 1-20
  -> 博睿康将 Trigger 写入脑电数据最后一个通道
  -> FBSCCA根据脑电数据输出 1-20，失败输出21
  -> 算法覆写 result.txt
  -> Unity读取标签并执行动态映射及车辆控制
```

算法同时通过 LSL 将判决结果返回刺激界面，用于同步更新 MetaBCI 内部的动态内容映射状态。

## 8. 正式版本改进建议

纯数字文件适合初步联调，但无法可靠区分连续出现的相同标签，也可能因快速覆写而漏掉中间结果。正式版本建议改为带递增序号的 JSON：

```json
{
  "version": 1,
  "sequence": 15,
  "label": 4,
  "status": "ok",
  "timestamp": 1750000000.123
}
```

判决失败示例：

```json
{
  "version": 1,
  "sequence": 16,
  "label": 21,
  "status": "prediction_failed",
  "timestamp": 1750000002.456
}
```

Unity只处理 `sequence` 大于上一次记录的结果。写入端建议先写临时文件，再以原子替换方式更新正式结果文件。
